# RIVALSNOTEBOOK v13.38 Release Notes

Built from the v13.37 deployment package.

## Regular Synergies and Counter Picks
- The normal **ADD SYNERGY** action now opens the one-to-one Synergy editor, not the Group Synergy Rule editor.
- Synergies and Counter Picks forms are restricted to **Hero : Hero** pairings. Group selectors are hidden and disabled outside the Groups page.
- The standard editors clear stale Group Rule mode before opening or saving.
- Editing a generated Group Synergy Rule from its card routes to the Groups page editor.

## Group Synergy Rules and Group Counters
- Group Synergy Rules require a Hero Group on at least one side.
- Group Counters require a Hero Group on at least one side and support **Group : Hero**, **Hero : Group** and **Group : Group**.
- The Groups page retains separate **ADD SYNERGY RULE** and **ADD GROUP COUNTER** buttons.
- Removed the modal-level **SWITCH TO GROUP SYNERGY / SWITCH TO GROUP COUNTER** buttons. Choose the rule type from the Groups page controls.
- Migrates legacy two-hero records accidentally stored in Group Synergy Rules / Group Counters into the corresponding regular one-to-one Synergy / Counter Pick collections.

## Allied Hero Roster count
- Keeps the Allied Hero Roster count label at **55 HEROES**, matching the Counter Picks registered count rather than overwriting it with the 57-entry local roster array length.

## Submission attribution
- Adds `submittedByName: "Developer"` and `submittedByEmail: "pocholoansay@gmail.com"` to new Developer-submitted Synergies, Counter Picks, Hero Groups, Group Synergy Rules and Group Counter Rules.
- Backfills existing user-generated records identified by their custom record IDs / user-authored source labels and current custom Group collections.
- Displays **Submitted by - Developer** on the corresponding Synergy, Counter Pick, Group and Group Rule cards.
- Bundled reference records sourced from Marvel / Reddit are not relabelled as Developer submissions.

## Supabase setup visibility
- Hides the **Connect Supabase Project** configuration panel and its save button in the sign-in popout. The normal sign-in / sign-up controls remain.
- The browser configuration in `config.js` must still be supplied privately before account-based services can connect.

## Preserved
- v13.37 Reddit-style directional vote UI, account-owned votes, upvoted-only filters and migration support.
- v13.36 Synergies layout restoration, pen arrowhead scaling, Pocket Strat workflows and Saved Play protections.
- Existing map assets, Supabase schemas, collaboration and Community Groups code.

## Setup tasks still required
1. Fill `config.js` with the Supabase project URL and publishable/anon key. Never use the service-role key in browser code.
2. Run `supabase/schema.sql` in the same Supabase project if the core schema has not already been installed; verify with `supabase/verify_schema.sql`.
3. Run `supabase/migrations/20261126_community_vote_directions.sql` to enable downvotes and net scoring.
4. Enable the `public` schema in Supabase Data API settings, then test signed-in voting, collaboration links / real-time access, and public Community Groups with a second account.

## Validation
- Static JavaScript syntax checks passed for the modified core and cloud scripts.
- Full inline script syntax and live browser interaction testing remain recommended after deployment.
